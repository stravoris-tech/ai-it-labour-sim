# ai-it-labour-sim

A System Dynamics model of AI's impact on IT employment, contract mix and vendor viability, for India and onshore (North America and Europe), 2024-2040. It is a port of a Python prototype of an AnyLogic design. The goal is a tool for asking questions: run many simulations under chosen scenario levers and uncertainty, then chart the answer over any window.

Status: release 0.1.0. `phase8` is the default model; `phase7` is kept for prototype parity.

## Commands

- Run all Python through uv: `uv run ...`. Run `uv sync` after pulling.
- Gate: `uv run python scripts/gate.py`. Its verdict is its exit code.

## The gate

Every slice exits through it:

1. `ruff check .`
2. `ruff format --check .`
3. `mypy` (strict, over `src`, `tests`, `tools`, `scripts` and `examples`)
4. `pytest` (default markers), with the test count reported
5. Dash check with its positive control: no U+2014 or U+2013 in any text file (`LICENSE-DOCS` excepted)

CI runs the same gate on every push and pull request (job `gate`).

## Conventions

- Hyphens, never em or en dashes, in code, docs, commit messages and reports.
- Canadian/British spelling, as in the spec (labour, modelling).
- Model names mirror the spec (`BaseDemand`, `GCCAppealEnd`); ruff's naming rules are off for this reason.
- Time is in years, Euler integration, dt = 1/16, Year = 2024 + t. 2024-2026 is the calibration window.
- Parameters are passed in explicitly. No module-level mutable parameter state.
- Randomness only through an explicitly seeded generator passed in, never global RNG. Deterministic tests run with noise off.
- The scalar engine is the reference: it must stay bit-identical to the prototype. Any change to it needs a slice prompt that says so.
- Load the prototype only through `tools/reference_runner.py` (it disables bytecode writing). Never import from `reference/` directly.
- The batched engine is checked against the scalar engine at 1e-12; the scalar engine is checked against the prototype bit for bit.
- **Goldens are platform-bound.** Stored goldens are bit-equal only on the platform in `reference/goldens/MANIFEST.json` (`environment`: OS, machine, Python build); elsewhere compare them at the golden tolerance (`tests/helpers.py` `TOL`, 1e-12). Bit-for-bit checks between code paths compare live runs on the same machine.
- Batch-scalar parity assumes numpy's float64 kernels (`np.power`, `np.log`) match libm. On x86-64 CPUs with AVX-512 they do not: set `NPY_DISABLE_CPU_FEATURES="X86_V4 AVX512_ICL AVX512_SPR"` (x86-64 numpy builds only, never on ARM64 or macOS; CI sets it). The guard in `tests/conftest.py` fails the parity tests at once if the kernels differ; tests that need 1e-12 parity request its fixture `numpy_kernels_match_libm`.
- **Seeding.** `run_experiment` draws every sample in the parent from one `np.random.default_rng(seed)`, in the order the levers are declared. Never `SeedSequence.spawn` per chunk: samples must not depend on the chunking.
- **Chunk independence.** Results must be bit-identical for any `workers` and `chunk_size`: inputs are built in the parent, split into contiguous chunks and reassembled in chunk order. Workers are top-level functions (Windows spawn); `workers=1` runs in-process.
- **Validation.** `run_experiment` validates by default and raises one `ValidationError` listing every violation (domains, no-effect overrides, `AdoptC0`, joint constraints, calibration identities, time constants against dt, distribution supports). `validate=False` skips it; `BatchResult.finite` still marks failed runs.
- **Extras.** Outputs the prototype does not record live in `EXTRA_KEYS` (scalar `RunResult.extras` with `run(extras=True)`, batch `outputs`). The 317 row keys and every parity test stay unchanged. An extra may only read a value the step already holds, never a new formula.
- **Percentiles.** Bands use `aisim.experiment.results.pct`, the prototype's `pct` vectorised with its operation order. Never `np.quantile`: it differs by 1 ulp on some data.
- **Auto chunking.** `chunk_size=None` (the default) is `auto_chunk_size(n, workers)`: up to 200 runs in one chunk, in-process; otherwise `min(625, max(50, ceil(n / workers)))` (recon 05 C). An explicit `chunk_size` overrides it. Results are bit-identical either way.
- **Scenario pinning.** A scenario plus a sampled lever it sets is an error in `run_experiment`, as is fixed plus sampled. `run_scenarios` runs scenarios on the same draws and pins, per block, the sampled levers a scenario sets (`ScenarioResult.pinned`); each block equals the solo run bit for bit. There an override of a parameter a requested scenario sets is an error; in `run_experiment` the override wins.
- **Meta.** `ExperimentResult.meta` is JSON-safe (`experiment` as plain data, `git_commit`, `git_dirty`, `platform`). Keep it so: `json.dumps(result.meta)` is tested.
- **Charts.** matplotlib only (no plotly), as the optional extra `charts` and in the `dev` group. Figures are `Figure` objects on the Agg canvas, never `pyplot`. Every artist has a `gid`: `median:<key>`, `band:<key>`, `baseline:<key>`, `label:<key>`, `line:<name>`, `shade:calibration`, `bar:<target>:<lever>`; scenario axes are `scenario:<label>` or `key:<key>`, overlay lines `median:<key>@<label>`.
- **Chart tests are data-level.** Find artists by gid and compare `get_xydata()`, band path vertices and bar widths with the source arrays bit for bit. No image golden files, no pixel comparisons (bytes differ across platforms).
- **Colours.** One map, `aisim/charts/colours.py`: Okabe-Ito, a fixed colour per dimension value and per scenario. Never set colours ad hoc in a chart.
- **Units.** Y-labels come from `catalogue().unit`, with " (unit inferred)" where `unit_inferred` is true; `ylabel=` overrides. Ratios are labelled "ratio to <year>".
- **Calibration shading.** When the result has `perturb_from` set, charts shade 2024 to Y and label it "calibrated baseline until Y" (for example "calibrated baseline until 2026.5"). Otherwise they shade 2024-2026 and label it "calibration period 2024-2026". Never "history": without a perturb year, levers act from 2024, so runs disagree there. Default window 2024-2040.
- **Saved charts.** `charts.save` fixes the layout on first save and strips dates (PNG `Software`, SVG `Date`, PDF `CreationDate`), so repeat saves are byte-identical on one machine. Reports salt and prefix every SVG id per chart.
- **Perturb from year Y.** `Experiment.perturb_from` runs a two-phase run (`aisim.perturb`): phase 1 runs the calibrated baseline from 2024 to Y once (tiled in a batch, computed in the parent and passed to the chunks); phase 2 restarts from its state at Y with each run's parameters, without the S0 tilt. Y is on the dt grid and one per experiment. The row at Y is phase 2's; `mins` is the element-wise minimum of both phases and `finite` is `finite1 & finite2`. Never switch parameters inside the step.
- **Global-step indexing.** Engine restarts take `start_step`; recording cadence and noise paths are indexed by the global step from 2024, so a restarted run's rows line up with an uninterrupted run's. A restart on the grid is bit-exact, and Y = 2024 equals a plain run.
- **Re-anchoring.** The five 2024-anchored paths (`aW`, `VerifNow`, `LOBAuto`, `CreditCostPB`, `AICostPerUnit`) continue from their base value at Y (`aisim.params.Reanchor`) only for a run whose path inputs differ from the base; otherwise today's formula runs unchanged, so unchanged runs stay bit-identical. Choose per run with `if` (scalar) or `np.where` on the two complete results (batch), never by blending.
- **`level_2024`.** A parameter that describes 2024 itself is flagged in `domains.csv` and cannot differ from the baseline when `perturb_from` is after 2024 (validation). Flag any new 2024 level or stored calibration constant. The inputs of 2024-anchored paths that are not re-anchored (`validate.ANCHORED_RATES`: `DemandGrowth`, `ITBudgetGrowth`, `amax`) are rejected the same way (rule `anchored_rate`): re-anchoring them is deferred to a later slice, and the rule catches them meanwhile. `tornado_levers(perturb_from)` drops every lever whose range fails validation at that Y, so the lever set depends on Y.
- **Noise streams.** Run i's noise comes from `SeedSequence(noise_seed, spawn_key=(i,))`, i its index in the design (in `run_scenarios`, within its block), generated inside its chunk: never `SeedSequence.spawn`, never the lever-sampling stream. Exact OU, factor `exp(x)`, exactly 1 up to and including Y. No noise amplitude is built in.
- **Model selector.** `Experiment.model` (default `"phase8"`, `aisim.state.DEFAULT_MODEL`), `Params.baseline(model)`, `BatchParams.baseline(n, model=)` and `tornado_levers(perturb_from, model)` choose a named baseline. The one registry is `aisim.state.BASELINE_FILES` (model name to baseline file); every check reads it at call time (`models()`), so no module keeps its own list. Four models ship: `phase8` (the default), `phase7` (the prototype-parity reference), `phase8_highadoption` and `phase9` (the four feedback loops of slice 12, registered but not the default; `docs/model-changes-phase9.md`) (README "Models"); an unknown model raises `ValueError`, or joins the single `ValidationError` (rule `model`). Validation's baseline comparisons (C8, `level_2024`, anchored rates) use the selected model. `meta["experiment"]["model"]` and the report's "model" row record it.
- **Extension parameters.** A parameter the prototype does not have (today `AnnuityShare` and `AnnuityAnchorW`, the E2a annuity pricing term, the switch `OpeningsContinuous`, continuous openings, and the 15 loop parameters of `phase9`: the strengths `kR7`, `R6e`, `kViab`, `PriceFloor`, `AIDiscCeil`, `R10rc`, `R4a` and `R4aIN`, off at 0.0, and the shapes `R7Lcap`, `R6Theta`, `R6Cap`, `R6MargTime`, `C4FadeTime`, `C4Cap` and `MinSeekTime`, at their base values and inert while their strength is 0; `docs/model-changes-phase9.md`) is not in `baseline.json`, whose bytes stay the prototype's. Its default lives in `aisim.params.EXTENSION_DEFAULTS`: a strength parameter's default, 0.0, turns its term off, so existing models reproduce bit for bit, and a shape parameter defaults to its base value and is inert while its strength is 0. `Params.baseline` merges it after the file's scalars, and it has a `kind=extension` row in `parameters.csv` (which `tools/build_baseline.py` appends) and a `domains.csv` row.
- **Calibration tool.** `tools/calibrate.py` fits a model to the Phase 7 targets (`tools/calibration_targets.csv`, checked against `calibrate7.py` by `ast`) with the batched engine: `--fit` (least squares, as `calibrate7.py`) or `--profile name=lo,hi,step`, with `--fix` and `--bounds`, writing a fit JSON with its provenance. Driving the 11 FIT parameters reproduces `calib7.json` (slow test). Multi-start flags, whose defaults keep `calibrate7.py`'s single fit from `X0`: `--starts N` (Latin hypercube from one `np.random.default_rng(--seed)`; 0 is the single fit), `--seed`, `--tol`, `--diff-step`, `--procs` (one start per spawned process; results do not depend on it) and `--warm FIT.json` (one more start, last). The fit JSON records every start, the seed and the settings, with the best start's `fitted` and `fixed` at top level. `tools/build_model.py --spec PATH --out PATH` writes a model's baseline file: Phase 7 plus `EXTENSION_DEFAULTS`, the spec's `set`, the fit's `fitted` and the derived constants they move (`AdoptC0`), computed by `Params.with_overrides`.
- **Models are built, never hand-written.** A model's spec and fit live in `tools/models/<name>/` (`spec.json`, `fit.json`). It is built by `tools/calibrate.py` (the fit) then `tools/build_model.py` (`src/aisim/data/baseline_<name>.json`), registered in `BASELINE_FILES`, never by hand. Each baseline reproduces its fit's loss bit for bit and is byte-identical to `build_model.py`'s output (`tests/test_phase8.py`). Phase 8 goldens are regenerated with `tools/generate_goldens_phase8.py` only when a slice prompt says so; their manifests pin the baseline file's hash.
- **A second model in tests.** Tests that need a model with arbitrary changes use the `register_model` fixture (`tests/conftest.py`): it writes a temporary baseline (Phase 7 plus changes, `tests.helpers.FIXTURE_CHANGES` includes a `level_2024` change) and registers it with `monkeypatch.setitem(state.BASELINE_FILES, ...)`. A runtime-registered model exists in-process only: use `workers=1`.
- **numpy upgrades.** Bump numpy only on purpose. After any bump, check that CI passes on an AVX-512 runner (the diagnostic step prints `avx512f`). If numpy renames its x86 targets, the guard fails and prints the new `__cpu_dispatch__`; update `NPY_DISABLE_CPU_FEATURES` to match.
- **CI logs.** CI runs with `NPY_DISABLE_CPU_FEATURES` set, so "kernels match" in a CI log describes the pinned environment only, not an unpinned AVX-512 machine.
- Commits are conventional commits, with the subject under 72 characters.

## Workflow

- Never commit on `main`. One feature branch per slice.
- Each slice follows recon, build, verify. Slice and analysis prompts are written by the operator and saved locally to
  `temp/prompts/` (gitignored, so not in the repo).
- The command sequence per slice:
  - `/branch <name>`
  - `/recon <prompt>`
  - `/build-slice <prompt>`
  - `/verify-slice <prompt> <branch>` in a fresh session
  - then `/ship`, `/merge --squash`, `/cleanup`
- `/recon`, `/build-slice`, `/verify-slice` and `/analyze` are this repo's commands (`.claude/commands/`). `/branch`,
  `/ship`, `/merge`, `/cleanup`, `/run-slice` and `/check-slice` are the operator's own user-level commands, not part
  of this repo; `/run-slice` and `/check-slice` carry a .NET gate, so slices use `/build-slice` and `/verify-slice`.
- Minor decisions a prompt did not anticipate: take them and log them as D-rulings. Anything above minor: stop and ask.
- Every ship report has a friction log.
- Questions about the model's results go through `/analyze`, never into a feature branch.
